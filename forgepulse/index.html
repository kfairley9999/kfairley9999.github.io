Problem & solution

Keep PR signal and policy portable across repos.

The problem

Review load spikes; rules stay trapped.

AI-generated PRs spike review load, dependency graphs live in maintainers’ heads, and branch protection rules stay trapped per-repo inside GitHub’s web UI.

The fix

One service beside GitHub.

ForgePulse runs as an external HTTP service with per-workspace D1/SQLite state: scoring incoming PRs, recording why a job would fail over, walking dependency blast radius, and validating portable YAML policy.

Verified capabilities

Five modules in one service.

TriageGate

Scores PRs by contributor history, test presence, diff size, title quality, and AI signals, and outputs fast-track, standard-review, quarantine-bot-check, or block-policy.

PolicyVault

Portable YAML/JSON rules for protected paths (e.g. auth/, billing/) and line thresholds.

GraphSync

Breadth-first, cycle-safe traversal across repo dependency edges to compute downstream blast radius; excludes the source repo and persists edits.

CodeAtlas

Indexes symbols, paths, code owners, and historical PRs for instant lookup.

RunnerMesh

Priority queue with monotonic sequence and failover routing records when hosted runners degrade.

Verified webhooks

HMAC-verified GitHub pull_request webhooks per workspace; optional fine-grained PAT encrypted at rest to fetch changed file lists.

How it works

Scoring an AI PR, checking blast radius & editing policy.

  1. Connect a repo

    Add a repository webhook and secret — plus an optional encrypted fine-grained PAT for changed file lists.

  2. Score each PR

    TriageGate sorts incoming pull requests into fast-track, standard review, bot quarantine, or policy block.

  3. See the blast radius

    GraphSync walks downstream dependencies; CodeAtlas finds owners and past PRs.

  4. Keep policy portable

    PolicyVault rules live in YAML/JSON you can version and move between repos.

Honest scope

Prototype disclosures

  • Not a GitHub App yet — connects via repository webhook + secret (and optional fine-grained PAT).
  • RunnerMesh records routing decisions only and does not launch or dispatch CI runners.
  • Does not write check runs, labels, or comments back to GitHub yet; test presence is marked unknown rather than guessed when no file list is available.
FAQ

Questions, answered plainly.

Is ForgePulse a GitHub App?

Not yet. It connects through a repository webhook and secret, with an optional fine-grained PAT.

Will it post comments or labels on our PRs?

Not yet. It does not write check runs, labels, or comments back to GitHub.

Does RunnerMesh run our CI?

No. It records routing decisions only; it does not launch or dispatch runners.

Can I try it without connecting a repo?

Yes. The live playground gives you an isolated guest workspace that persists across refreshes.
