The problem

Agents fail at the tool boundary.

A model with an over-broad MCP server can write files, call a shell, or talk to another agent with more privilege than anyone intended. Most application scans never look at tool annotations, HTTP MCP posture, or who is allowed to approve a dangerous call.

  • Prompt injection & goal hijack
  • Excessive agency
  • Dishonest tool annotations
  • Missing HTTP auth
  • Missing rate limits
  • Unsafe sinks
  • Privilege escalation via delegation
  • Replayable audit trails

How it’s done

I audit with tools I actually maintain.

Every engagement is a human review. The tools below produce evidence; they do not replace judgment, and a clean scanner report is not a guarantee of safety.

Scanner

MCPSentry

Static rules MCP001–MCP008, plus an optional live tools/list probe that does not invoke tools.

Looks for dishonest annotations, over-broad parameters, unsafe sinks, hardcoded secrets, prompt-injection in descriptions, missing HTTP auth or rate limits, and known npm CVEs.

Policy layer

AgentGate

Least-privilege allow-lists, approval hooks, and hash-chained audit logs.

Used in Standard and Deep as a policy review — which tools should be allowed, which need a person in the loop, and where identity is being taken from model text (which is not a policy).

Trace & replay

AgentReplay

Append-only traces and a diff that shows where two runs diverged.

Used in the Deep tier when a staging trace can be recorded or provided. It is a debugger, not a security boundary, and the report will say so.

Frameworks

Mapped to OWASP and NIST AI RMF.

The report will say “not assessed” when a category was out of depth for the chosen tier. That is deliberate.

AreaWhat I look at
OWASP LLM 2026Prompt injection, sensitive data, excessive agency, supply-chain CVEs (npm / OSV), unbounded consumption, and related entries as evidence allows.
OWASP Agentic 2026Goal hijack, tool misuse, privilege abuse, unexpected code execution, memory poisoning, and inter-agent delegation.
NIST AI RMFMap the system boundary and intended use; Measure the controls with evidence; recommend Govern / Manage next steps. I do not operate your governance program, and this is not a certification.

Honest limits

What this audit is not.

  • Not a SOC 2, ISO 27001, CMMC, FedRAMP, or EU AI Act certification — I don’t have those.
  • Not a guarantee that every issue will be found. Static analysis is heuristic, not a formal proof.
  • Not a claim that fixture scores from my test corpus apply to every server you run.
  • AgentGate only constrains calls that go through it, and its included red-team suite has two documented residual misses.
  • I don’t invoke destructive tools, and I don’t publish client findings without written approval.
