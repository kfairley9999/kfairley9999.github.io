Problem & solution

Keep the call list out of loose sticky notes.

The problem

Leads scatter while you’re on the job.

When a shop owner is on a job site, leads arrive across voicemails, texts, and web forms. Follow-ups slip, stale quotes sit for weeks, and general-purpose AI chats hallucinate priorities or lose track of dollar amounts.

The fix

The model talks. LeadFlow keeps the books.

The host model handles conversation; LeadFlow owns the books. Every call is Zod-validated, money is stored in integer cents, and scores are computed deterministically from a published rubric—never guessed by an LLM.

Verified capabilities

What the code actually does.

Eleven MCP tools, three resources and two prompts.

Leads with safe writes

create_lead & update_lead with idempotency keys and optimistic locking (expectedUpdatedAt).

Search everything

get_lead & search_leads across name, service, city, email, phone, and notes.

Every touchpoint logged

log_interaction across call, email, SMS, visit, or note.

Follow-ups that surface

schedule_follow_up, set_follow_up_status, and list_due_follow_ups.

Deterministic 0–100 rubric

Source: referral (+22), website (+14), walk-in (+12), phone (+8), other (+3). Reachability: phone (+10), email (+8), unreachable (−12). High urgency (+20); job value up to +16 ($5,000+). Proposal (+16), active ≤2d (+16), quiet >21d (−18). Bands: hot (75+), warm (50+), cool (25+), cold.

Resources, prompts & safety

Resources leadflow://pipeline, leadflow://scoring-model, leadflow://lead/{id}; morning-brief and grounded follow-up prompts; bearer-token guard on /mcp; pipeline_summary and formula-safe export_leads_csv that escapes leading =, +, -, @.

How it works

From voicemail to a ranked call list.

  1. Connect your MCP client

    Run LeadFlow over stdio on local SQLite, or on Cloudflare Workers + D1 over Streamable HTTP behind a bearer token.

  2. Capture and log

    Ask Claude or Cursor to add leads and log calls, emails, SMS, and visits. Every input is Zod-validated.

  3. Score with the rubric

    Each lead gets a deterministic 0–100 score and a hot / warm / cool / cold band from the published model.

  4. Work the morning brief

    Due follow-ups, the pipeline summary, and grounded follow-up drafts — all from the same records.

FAQ

Questions, answered plainly.

Does an LLM decide which leads are hot?

No. Scores come from a published, deterministic rubric. The model calls the tools; it does not invent the score.

What does it cost to run?

The code is MIT open source and free to self-host. It uses no paid external APIs on the tool path.

Where does my data live?

In local SQLite when you run it over stdio, or in your own Cloudflare D1 database when deployed to Workers.

Is the live demo real customer data?

No. It uses a fictional dataset, Northglass Plumbing, and the public endpoints return zero lead records.
